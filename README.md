# 羽迹 · 羽毛球成长记录空间

一个用于**长期追踪羽毛球水平进步**的单文件网页应用。零依赖、无需联网、无需安装，数据保存在本机浏览器中。
默认面向**双打**场景设计：搭档与对手都是一等实体。

## 快速开始

直接双击 `index.html` 用浏览器打开即可（推荐 Chrome / Edge / Safari 最新版）。

首次打开会自带一批示例数据（约 12 周的双打为主训练与比赛记录），方便你立刻看到图表效果。
这些示例可通过「个人设置 → 清空全部数据」一键清除，然后开始记录你自己的数据。

## 功能模块

|---|---|

| **训练比赛** | 记录每次训练与比赛：日期、项目（单打/双打/混双/训练/其他）、时长、搭档、对手 1/2、比分（多局）、场地、强度 RPE、感受、标签、备注；按项目/结果（含**待补录比分**）/球友/日期/关键词筛选；保存时自动为搭档与对手建档 |

| **专项自评** | 连续表单式逐项自评（从「技术评估」页进入，不进侧边导航）：每项给出**可计数观测题 → 折算建议分 → 四档行为锚点校准**，支持草稿续填、沿用上次、进度条与分节跳转 |
| **搭档档案** | 自动从比赛记录归档搭档，统计配合场次、配合胜率、最默契搭档排行、项目分布；支持「补填搭档」批量回填历史比赛；搭档详情含滚动配合胜率趋势与搭档反馈 |
| **对手档案** | 双视图：**按组合**（如「老张 + 阿强」作为一个固定组合统计）与**按个人**（组合拆开逐人计数，含与各搭档的分项战绩）；展示交手场次、胜负、胜率、总得分与时间线 |
| **目标里程碑** | 阶段性目标（如「战胜老张一次」「杀球评分达到 8 分」）、衡量标准、截止日期、分解步骤勾选自动计算进度、逾期提醒 |

## 双打数据模型

一场双打比赛涉及「我 + 搭档 VS 对手组合」，本应用用两个维度同时表达：

- `partner`：我的搭档（单值），用于**配合**统计（哪些搭档跟你赢得多）。
- `opponents[]`：对手列表（1–2 人），既按**组合**统计（固定搭档组合战绩），也可拆开按**个人**统计（某人的个人交手记录）。
- `relation` 字段记录球友与你的关系：`opponent` / `partner` / `both`，同一人既搭档过又对阵过会自动升级为 `both`。
- `avatar`：**可选**头像 key，指向内置头像库。缺省或写坏时自动退回「色块 + 姓名首字」，老档案零影响，`migrate()` 不碰这个字段。

> 单打记录同样兼容：`partner` 留空、`opponents` 只填 1 人即可。

### 名单 = 统计 ∪ 档案（容易踩的坑）

搭档页和对手页的名单由**两个来源合并**而成，两者必须同时认，缺一个就会出现"加了人却像没加上"：

| 来源 | 内容 | 谁产生 |
|---|---|---|
| **统计** | 有比赛记录的人（场次 / 胜负 / 胜率 / 最近交手） | 从 `sessions` 派生，只认**已录入比分**的比赛 |
| **档案** | 手动建立的球友（可为 0 场） | 「添加搭档 / 添加对手」写入 `state.rivals` |

合并规则（`withRoster()`）：

- **场次多的在前，0 场的排最后**；筛选器「我占优 / 我落后」天然把 0 场的滤掉（它们胜负都是 0）。
- **0 场行单独表述**：标「还没打过 / 还没交手」，不画胜率进度条，胜率显示 `—` 而不是 `0%` —— 后者看起来像"一场没赢"，而真相是"一场没打"。
- **统计卡只认真正打过的人**（「对手人数」= 交过手的人数），否则数字会虚高；档案总数另起一句「已建档 N 人」。
- 对手「按组合」视图也会补入未交手的人（一个新档案就是一个"还没交手过的单人组合"）。补入时会跳过**已经出现在某个组合里**的人 —— 否则老张既在「老陈 + 老张」里，又被单独补一行，整个列表重复。

另一条硬规则：**同名只允许一条档案**（`upsertRival()`）。全站都用 `rivals.find(x => x.name === ...)` 取档案，一旦出现两条同名记录，第二条就永远显示不出来、也永远改不到。所以新增撞名时是**合并**而不是再 push 一条：

- 把另一个身份补上，`relation` 升级为 `both`（本来是对手、现在也加成搭档），已经是 `both` 的不降级。
- 未填的 `level` / `note` 用**已有值**，不被空值冲掉。
- **颜色与头像只在这次真的动过时才覆盖** —— 新增弹窗的默认色是固定值，若不区分"没动过"和"主动清空"，就会把人家已设好的头像冲掉。
- 编辑时改名撞上别人 → 直接拒绝，让用户换个名字。

## 球友头像库

给搭档和对手设置头像：**个人设置之外的任何页面都不用改**，头像只挂在档案上，列表、详情抬头、编辑弹窗三处自动生效。

### 16 款，但只有 ~20 个形状函数

不是画 16 份独立的 SVG，而是「**1 个通用半身像 + 4 个可复用槽位**」参数化生成：

```
通用半身像：底色圆 + 颈 + 肩(带衣领) + 耳 + 头
槽位（每款只声明差异）：
  back  脑后 → 马尾 / 长发 / 丸子 / 猫耳 / 狐耳 / 兔耳 / 熊猫耳   （画在头之前，会被头挡住一部分）
  hair  发型 → 刺猬 / 圆盖 / 侧分 / 寸头 / 呆毛 / 卷发 / 光头
  face  五官 → 常态 / 锐利 / 平静 / 开心 / 眨眼 / 呐喊 / 动物 / 熊猫 / 狐狸 / 兔
  acc   配件 → 发带 / 鸭舌帽 / 反戴帽 / 眼镜 / 口哨 / 八字胡 / 胡须
```

加一款头像 = 在 `AV_MAP` 里加一行声明；加一种发型 = 在 `AV_HAIR` 里加一个函数。渲染代码不用动。

| 12 款人物 | 4 款动物 |
|---|---|
| 扣杀型 / 网前型 / 眼镜哥 / 新手上路 / 教练 / 速度型 / 力量型 / 技巧型 / 丸子头 / 老球友 / 少年 / 卷发 | 熊猫 / 猫 / 狐狸 / 兔子 |

### 两条决定观感的约定

1. **底色与球衣跟随用户自选的 `color`**（底色是 `color-mix(in srgb, 色 20%, var(--bg-elev))` 的半透明染色）。
   这样「头像颜色」这个老字段继续有意义，16 款 × 10 色足够区分，**同一个人换个颜色就是一个新头像**——换色时选择器里的小样会实时跟着变。
2. **配件用固定色卡，不跟主题语义色**。否则会出现深色主题下帽子变绿（`--loss`）这类误读，也会和自选球衣撞色。墨线统一 `var(--ink)`，所以深浅两套主题自动适配。

### 兜底与容错

- 没设头像 → 退回**色块 + 姓名首字**（原行为，未改动）。
- `avatar` 写了不存在的 key → 走**同一条兜底路径**（归一化集中在 `avKey()`，两种坏数据不会各自分叉）。
- 对手页「按组合」视图里，≥2 人的组合**刻意不用某个人的头像**，而是保持「人数色块」——组合不是一个人，视觉上要能和单人行区分开。
- **颜色的唯一来源是档案里的 `color`**：搭档列表、对手列表、详情抬头三处都从档案取色（对手列表原先用 `hashColor(名字)` 派生，会让「编辑档案」里选的颜色到不了这一页，已修正并有断言兜底）。
- 目标尺寸是列表里的 **42px**：所以形状粗、无细线、细节 ≤3 处。`preview-avatars.png` 里有 42px 实拍和放大两版对照。

## 比分与胜负口径

- 比分格式：`21-19,17-21,21-15`（多局用逗号分隔，**我方比分在前**），只记总分即可。
- 「比赛」判定：**有比分** 或 **标记为「比赛」类型** 的场次都会计入场次统计。
- **胜率分母只算已录入比分的场次**，避免漏填比分把胜率拉低；标记了比赛但未录比分的场次会单独显示为「待补录」，仪表盘顶部会自动提醒并提供「去补录」入口。

### 为什么不做逐分记分板

早期版本带过一个「记分板」：可以边打边逐分点记，也可以只记里程碑（换边 / 11 分间歇 / 局末）的**分段**记分，并据此算出关键分得分率、最长连续得失分、发球轮表现。

**这一整套已全部移除**，理由是：

| 问题 | 说明 |
|---|---|
| 场上做不到 | 每分都停下来点一次手机在真实对抗中不现实；那类交互属于**专业记分 App**，不是一个"成长记录工具"的职责 |
| 连带的 UI 负担 | 为了两种精度，需要大数字显示、序列圆点、双模式切换、撤销、跳局、局间管理……一个附属功能和"记录比赛结果"本身一样重 |
| 数据诚实性 | 里程碑展开成序列只能还原出**近似**节奏，"最长连续得分"这类指标本身就是不可信的，只能做下限用，容易误导 |

结论：**采集侧只保留"赛后填一个总比分"**。这让记录成本降到一次输入，也让积分、胜率、搭档/对手战绩、趋势这些真正长期有用的统计口径保持干净。

## 下一步该练什么（短板诊断）

「技术评估」页会自动给出一张**下一步该练什么**卡片，这是全站唯一的"教练型"功能，它的输入**只有你已有的自评数据**——评过自评就自动有结论，不需要额外填任何东西。

诊断是**规则数组**驱动（`DIAG_RULES` / `DIAG_GOOD`），每条规则是一个纯函数：吃预计算好的上下文，吐一组建议或空数组。加规则 = 往数组里加一项，渲染代码不用动。

| 规则 | 触发条件 | 输出 |
|---|---|---|
| `weak` | 某项自评 < 5 分 | **补短板**（权重按缺口放大） |
| `below` | 已评 ≥ 6 项，且某项比自身平均水位低 1.2 分以上 | **拉齐水位** |
| `stall` | 同一项连续两次自评差值 < 0.3 且仍 < 8 分 | **换练法**（现有练法推不动了） |
| `stale` | 距上次自评 > 45 天 | **该复评了** |
| `up` / `peak`（正向组） | 单项涨幅 ≥ 0.8 分 / 已达 8.5 分以上 | **涨得最快** / **可以当武器** |

- 同一专项命中多条规则时只保留权重最高的一条（`diagDedupe`），待办最多 3 条、按权重降序，正向组最多 2 条——避免卡片变成一屏坏消息。
- 每条建议都带**为什么**（引用你的实际分数）和**怎么练**（来自 18 条练习库 `DRILLS`，每条都带组数 / 次数 / 时长等可执行量）。
- `DRILLS` 与评分标准 `TECH_ITEMS` **完全解耦**：练法不挂在专项对象上，两边各自独立维护。
- 没有任何自评数据时整张卡片不渲染（不会出现空卡）。

## 专项自评：怎么打分

自评不再是"凭感觉给个分"，而是三步走，让不同月份的分数可比：

| 步骤 | 做法 | 解决的问题 |
|---|---|---|
| **1. 固定观察窗口** | 每道观测题都锁定一个可数窗口，如"连续发 10 次小球，过网且落点在对方前发球线后 30cm 以内的次数" | 避免"今天感觉不错"这种无法复现的判断 |
| **2. 先答观测题，折算建议分** | 每项 2 道观测题，各 4 档（0–3 分）。等权求和后线性映射到 1–10：`1 + 得分 × 9 / 满分`，保留一位小数（2.5 / 5.5 / 8.5 这类半分不丢） | 分数由**行为频次**推导，不靠主观印象 |
| **3. 四档行为锚点校准** | 每项给出 1–3 / 4–6 / 7–8 / 9–10 四档的行为描述，拖动滑杆时实时显示当前落在哪一档 | 让"7 分"和"8 分"有明确边界 |

- **统一自评口径**：只采信 `by: "self"` 的自评记录。历史遗留的教练 / 球友外部评价**不删除**，但不再参与当前分与趋势计算，可在「技术评估」页通过「查看历史外部评价」单独查阅。
- **允许半途而废**：表单是连续长表单，填到一半切走页面草稿仍在；也支持「沿用上次」把上批次答案整批复制过来微调。同一 `(日期, 专项)` 重复保存会覆盖，不会产生重复记录。

## 数据存储与备份

- 数据保存在浏览器 **localStorage**（键名 `badminton.log.v1`），不上传任何服务器。
- **换设备 / 清理浏览器数据前请先导出备份**：「个人设置 → 导出 JSON 备份」。
- 「导入 JSON」支持与现有数据**按 ID 合并**，不会整份覆盖，可安全地在多台设备间同步。
- 「导出记录 CSV」带 BOM，列含日期/项目/搭档/对手/比分等，可直接用 Excel 打开做二次分析。
- 「打印 / 存 PDF」已做打印样式优化，会自动隐藏导航。

## 交互提示

- 桌面端：左侧导航 + 顶部统计范围切换（30 天 / 90 天 / 1 年 / 全部）。侧边栏按「总览 / 记录 / 成长 / 系统」分组，列出全部页面。
- 移动端：底部标签栏只保留 4 个高频入口（**总览 / 记录 / 技术 / 目标**）+ **「更多」**；搭档档案、对手档案、训练日记、个人设置收进「更多」贴底面板。右下角悬浮「+」快速记录。
- 移动端导航由 `PAGES` 的 `inMore` 标记驱动：不标 `inMore` 的可见页面自动进底部 Tab，标注的进「更多」面板。两者并集恒等于全部可见页面，**新增页面不可能在移动端消失**（有回归断言兜底）。Tab 短标签用独立的 `short` 字段（2 字且全局唯一），避免「训练比赛 / 训练日记」都被截成「训练」。
- 快捷键：按 `n` 快速新建记录；弹窗内按 `Esc` 关闭。
- 主题：左下角按钮切换浅色 / 深色，偏好会被记住。
- 新建记录时：选择「双打 / 混双」会自动出现搭档与第二名对手输入框，并实时预览胜负结果。

## 测试

```bash
node tests/run_tests.cjs          # 核心逻辑回归（75 项）
node tests/run_render_tests.cjs   # 页面渲染冒烟 + 响应式 + 移动端导航 + 头像库（68 项）
node tests/run_doubles_tests.cjs  # 双打/搭档/档案 + 花名册合并（80 项）
node tests/run_assess_tests.cjs   # 自评标准与表单（32 项）
node tests/run_insight_tests.cjs  # 短板诊断 + 练习库 + 反臃肿守卫（30 项）
node tests/run_pwa_tests.cjs      # 角色几何 + 图标 + manifest/sw/icons 文件级校验（40 项）
node tests/run_pwa_e2e.cjs        # 真浏览器端到端：可安装性 / SW / 离线（23 项）
```

前六个脚本可在无浏览器环境下运行（内置极简 DOM 桩），合计 **325 项断言全绿**；
`run_pwa_e2e.cjs` 会自己起静态服务 + 起无头 Edge，通过 DevTools 协议做**浏览器级**验证
（找不到浏览器就跳过，不算失败），**23 项全绿**。

`run_pwa_tests.cjs` 守的是「改角色别把图标忘掉」：它断言图标与小羽共用同一份本体几何、
羽裙顶边必须正好 7 段羽尖、表情锚点（软木托 `translate(60,99)` + 眼 `y=105`）不许漂移、
`file://` 下不许渲染安装入口，并直接读仓库文件核对 manifest 必填字段、
每个 PNG 的实际尺寸与声明尺寸、maskable 四角是否实底、SW 预缓存清单里的文件是否都存在。
最后三条是**防倒退**：旧的蓝三角 favicon、旧的三瓣叶片路径、旧的碗口椭圆都不许再出现。

`run_pwa_e2e.cjs` 不写死任何结论，全部问浏览器自己要：清单解析结果、安装判据、SW 是否接管、
缓存里到底有什么、断网后页面还剩几项导航。

其中 `run_insight_tests.cjs` 的第 5 节是**反臃肿守卫**：它逐条断言被移除的记分能力（`scoreboard` / `sbTally` / `roundsAggregate` / `marksToSeq` / `demoSeq` / `roundsBlockHTML` / `.sb-*` 样式 / `rounds` 字段 / 「逐分」文案 …）在源码里**不存在**，同时断言诊断卡仍然可用。这样删除结果被锁死，不会在某次改动里悄悄回流。

`run_render_tests.cjs` 里的头像库用例则锁三件事：**款式完整性**（16 款、key 唯一、每款都能生成完整 SVG）、**生成器不漏模板变量**（参数化方案唯一的新风险）、以及**兜底路径唯一**（老数据缺字段和乱填 key 走同一条分支）。`run_doubles_tests.cjs` 从数据侧补一刀：示例档案的头像 key 必须合法（写错不会报错，只会静默退回首字，很难发现），且 `migrate()` 不得改写它。

花名册合并那批用例守的是另一件事：**手动建档的人必须出现在名单里**（用户曾经报「添加的搭档无法保存」），以及**同名绝不重复建档**（两条同名档案会让第二条永远显示不出来也改不到）。

**写 DOM 桩测试的坑**：`root.innerHTML = "..."` 只是存一个字符串，**不会真的创建子节点**，而 `$("#list")` 走 `querySelector` 返回的是独立占位元素。所以「列表里有没有某一行」必须取 `qs("#list").innerHTML`，不能用 `host.innerHTML` —— 后者只看得到页面骨架。


## 视觉设计：趣味插画（Playful Illustration）

### 角色设定 —— 小羽

界面里住着一只叫**小羽**的羽毛球。它的性格是**元气搭档**：爱鼓励、量化但不冰冷、偶尔嘴贫。
颜色、字体、插画与文案全都是这一个人格的不同侧面，不是各走各的。

| 维度 | 做法 |
|---|---|
| **颜色** | 奶油宣纸底 `#FFF7EF` + 墨紫描边 `#2C2740`；品牌橙 `#FF7A45`、天蓝 `#4F9DF7`、葡萄紫 `#A78BFA`、蜂蜜黄 `#F2A413` |
| **字体** | 不请求任何外部字体（离线/国内可用）。展示型文字走 `ui-rounded / SF Pro Rounded / PingFang SC` 圆体栈 + 800 字重 + 收紧字距；正文走常规栈 |
| **插画** | 全内联 SVG。小羽有 8 种表情（happy / cheer / win / think / sleep / coach / wave / sad）+ 8 张场景涂鸦（球场 / 搭档 / 对阵 / 雷达 / 目标旗 / 日记本 / 奖杯 / 数据柱），随主题变量自动适配深浅色 |
| **头像** | 球友可用 16 款头像（12 人物 + 4 动物），与插画同一套墨线语言：粗描边、圆润造型、固定糖果色。详见「球友头像库」 |
| **文案** | 第二人称、口语、动词优先。成功=短促欢呼（「拿下这一场！」），空状态=邀请而非指责（「还没上场？先记一场吧」），低谷=鼓励而非评判（「低谷期也是积累期」） |

### 小羽的身体：三个特征决定「像不像羽毛球」

第一版被吐槽过 —— 三片窄花瓣插在一个带沿的碗里，远看像盆栽。重画时只抓三个识别特征，
少一个都不像：

| 特征 | 画法 | 为什么 |
|---|---|---|
| **波浪羽尖** | 顶边由 7 段半圆构成 | 羽裙顶端是一圈羽尖，这是最强的远距识别信号；画成一条直线就变成「灯罩」 |
| **扇形羽轴 + 两道横线** | 6 条细线从束口扇向羽尖，加 2 道横弧 | 真球有羽轴与交叉绑线，这层网格肌理是第二识别信号 |
| **束口色带 + 半球软木托** | 42×10 的圆角色带 + 40×46 的椭圆托 | 把「裙」和「托」切成上下两段。托再大就变「灯罩扣球」，收口再宽就变「方」 |

比例是硬指标：**羽裙顶宽 70 ︰ 收口 40 ︰ 软木托 40**，锥度不够就会显方。

**脸长在软木托上**，锚点被刻意冻住：软木托 = `translate(60,99)` 之后的半球，局部 y∈[0,23]；
眼睛固定在 `y=105`（距托顶 6）、嘴从 `y=110` 起。换身体几何时这两个数**不能动**，
否则 8 个表情会集体脱位 —— `run_pwa_tests.cjs` 里有断言钉住这一点。

`shuttleBody()` 是**唯一**一份球体几何，同时被四处使用：小羽本体、场景涂鸦的 `miniShuttle()`、
侧栏品牌标、以及 App 图标 `appIconSVG()`。改角色只改这一处，不会出现「图标是另一只球」。
各尺寸的表情挂饰（星星、气泡、Z、手臂）在羽裙变宽后逐个让位到球体外侧，否则会压在羽毛上。

### 四条设计原则的落地

1. **把夸张留给重点** —— 全站只有四处"大声"：Hero 区（粗描边 + 硬偏移投影 + 荧光笔划线的大标题）、主按钮（贴纸式硬边）、模态框、以及达成目标时的彩带。统计卡、表格、图表一律安静：细描边、克制的留白、12–14px 正文。
2. **圆润不等于含糊** —— 圆角按 8/12/16/22/28px 五级统一；但**每个可交互元素都有实描边和明确文字**：按钮 1.5px（主按钮 2px 墨色）、输入框 1.5px 且聚焦有 4px 光环、状态徽章带边框 + 胜/负/平文字。
3. **动效表达因果** —— 按压 110ms 即时回弹、页面进入 320ms 依次浮现（延迟封顶 120ms，整体 ≤440ms）、进度条 620ms 弹性填充、达成目标弹彩带。**全部动效都收在 460ms 内**，不拖慢操作。
4. **可关闭** —— 完整支持 `prefers-reduced-motion: reduce`，一键停掉所有动画与彩带。

### 语义色约定（沿用原版，未改动）

本应用的「胜 / 负」与「上涨 / 下跌」沿用原版约定：
**胜 = 暖玫红 `--win`**，**负 = 薄荷绿 `--loss`**（下跌同理）；而「成功 / 达成」用绿、「危险 / 删除」用红。
换配色时请保持这套映射，否则会把"胜率"的颜色含义改掉。

### 想换配色 / 加矢量角色

- 全部颜色集中在 `<style>` 顶部的 `:root` 与 `html[data-theme="dark"]` 两块令牌里，改令牌即可换肤；组件不写死颜色。
- 角色的**身体**在 `shuttleBody()`（一份参数化的几何：换色 / 加粗 / 去掉网格线都是参数），**表情**在 `MASCOT_FACE`，**场景**在 `ILLOS` 三张表里。改身体只改 `shuttleBody()`，小羽 / 涂鸦 / 品牌标 / App 图标会一起变；加一个场景 = `ILLOS` 加一行 key。
- 品牌色改了要重跑 `node tools/make-icons.cjs` 重新生成 `icons/*.png`（favicon 是运行时现算的，不用管）。
- 头像在 `AV_MAP` + `AV_HAIR` / `AV_BACK` / `AV_FACE` / `AV_ACC` 四张槽位表里：加一款 = `AV_MAP` 加一行，加一种发型/配件 = 对应槽位表加一个函数。列表与详情统一走 `avatarHTML(姓名, 颜色, key)`。
- 若想换成真正的圆体中文（如站酷快乐体），只需在 `<head>` 加一行字体引入，并把 `--font-display` 的首位改成该字体族即可 —— 当前默认不引入是为了保证**零依赖与离线可用**。

## 网页图标与可安装（PWA）

### 图标

- **网页图标（favicon）**：启动时由 `appIconSVG(64)` 现算成 data URI 塞进 `<link rel=icon>` —— 零请求、离线可用。head 里先放一块品牌橙占位，避免首帧没有图标。
- **应用图标**：`icons/` 下四个 PNG（192 / 512 / 512 maskable / 180 apple-touch），全部由 **`node tools/make-icons.cjs` 生成** —— 它从 index.html 里把 `appIconSVG` 抠出来跑一遍，写成一页 HTML 交给无头浏览器截图。所以图标与角色永远同源，改角色重跑一次即可。
- 生成器里记了两个实测坑：① 无头 Edge 的布局视口有下限（宽 `max(504, 窗口宽)`、高 `窗口高 − 95`），「窗口设 192 就能得到干净 192×192 截图」是错的，会截到失真的图；② 截图与布局是 1:1、左上对齐。于是改成 **画布固定 px×px 摆在左上角，再裁出左上 px×px**（`tools/png.cjs`：手写的极简 PNG 解码 / 裁剪 / 重编码，因为环境里没有 Pillow / sharp / canvas）。

### 安装到桌面

把整个目录托管到任意 http(s) 静态服务器即可安装（地址栏会出现安装图标）；
也可以从应用内 **个人设置 → 安装到桌面** 一键装。

| 文件 | 作用 |
|---|---|
| `manifest.webmanifest` | 名称、图标、`display: standalone`、主题色，以及两个右键快捷方式（记一场 / 自评） |
| `sw.js` | Service Worker：App Shell 预缓存；**导航请求走网络优先**（改了代码能生效），断网回落缓存；图标等静态资源缓存优先 + 后台更新 |
| `icons/*.png` | 应用图标，由角色几何生成 |

**不托管也照样能用**：`file://` 双击打开时整段 PWA 逻辑静默跳过（`PWA.can` 为假）——
不注入 manifest、不注册 SW、设置页也不出现安装入口。单文件、零依赖、双击即用的性质没变，
那三个伴随文件不被读取，功能一点不少。

「能装」不接受自我感觉，只认浏览器给的结论：`tests/run_pwa_e2e.cjs` 通过 DevTools 协议问
`Page.getInstallabilityErrors`，**空数组才算过**；同时验证 SW 接管、缓存清单、
真实点击安装按钮，以及**断网后重载仍能打开**。

## 技术说明

- 单文件 HTML，约 299 KB，内含全部 CSS 与 JavaScript（PWA 的三个伴随文件不含在内，也不被读取）。
- 图表为**自研原生 SVG 渲染**（折线 / 柱状 / 雷达 / 环形 / 火花线），无任何第三方库。
- 响应式断点：`1080px`（统计卡降列）、`920px`（切换为移动端导航，所有栅格堆为单列）、`560px`（紧凑间距）。
- **栅格列宽一律用类名，禁止内联 `grid-template-columns`**：内联样式优先级高于样式表，会顶掉 `@media(max-width:920px)` 的单列堆叠规则，导致小屏卡片被压成两列、标题竖排。非等宽列用 `.ratio-16-10` / `.ratio-13-10` / `.ratio-10-12`，断点内已一并覆盖（`run_render_tests.cjs` 有断言兜底）。**唯一例外是头像网格 `.av-grid`**：它用 `repeat(auto-fill, minmax(58px,1fr))`，靠换行自然堆叠，不需要（也不该）写单列规则。
- **反臃肿约定**：新能力一律"挂载"到既有页面、复用既有的 `card` / `stat` / `grid` / 按钮组件，不新增页面、不新增顶级数据集合、不引入新的颜色体系（全部走既有 CSS 令牌，深浅两套主题自动适配）。新增数据的默认形态是**既有集合上的一个可选字段**，而不是新建一个集合。诊断卡和头像库都是这条约定的产物：诊断只做计算（`§4b` 区块**不生成任何 DOM**），头像只做生成（16 款收敛成 1 个通用半身像 + 4 个可复用槽位），渲染全部复用既有组件。
- 数据模型带 `version` 字段与 `migrate()` 容错：v1（单打为主）升级到 v2（双打）时**不丢任何历史数据**，会自动推断项目类型、把旧的 `opponent` 迁移为 `opponents[0]`、并回填搭档与对手档案。
